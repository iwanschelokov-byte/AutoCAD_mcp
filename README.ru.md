# Плагин AutoCAD MCP

> **Это форк.** Исходный репозиторий `NCO-1986/AutoCAD_mcp` стал недоступен
> 18 августа 2026 года, вскоре после выпуска версии 2.0.0. Форк содержит этот
> релиз плюс исправления, описанные в `CHANGELOG.md` под номером 2.0.1, и
> существует, чтобы работа оставалась доступной и собираемой — прежде всего под
> AutoCAD 2027, на котором она и проверяется. Авторство в истории коммитов не
> менялось, лицензия остаётся той же, что была заявлена в исходном README: MIT.
> Если исходный репозиторий вернётся, эти изменения будут предложены ему
> отдельным pull request.
>
> English version: [README.md](README.md). Перевод следует английскому
> оригиналу; при расхождениях верным считается он.

Автоматизация AutoCAD с помощью ИИ через **Model Context Protocol (MCP)**. Позволяет Claude и другим ИИ-ассистентам создавать, изменять, запрашивать, искать и визуально проверять чертежи AutoCAD на естественном языке.

> «Начерти план этажа с 3 спальнями» — и он это делает.
> «Найди аккумуляторную ближе всего к санузлу» — и он переходит туда.
> «Сделай снимок экрана и проверь, правильно ли выглядит лист» — и он проверяет визуально.

## Архитектура

```
┌─────────────┐                ┌────────────────────┐
│  Claude /   │ ─── stdio ───▶ │  MCP server        │
│  AI Client  │      MCP       │  autocad-mcp-server│ ─┐
└─────────────┘                └────────────────────┘  │
                                                        │  TCP JSON-RPC 2.0
                                                        │  localhost:8081
┌──────────────┐        HTTP / JSON-RPC 2.0             ▼
│   Browser    │ ──────────────────────────▶ ┌──────────────────┐
│   (web app)  │  127.0.0.1:8082/jsonrpc     │  C# Plugin       │
└──────────────┘  (CORS + Chrome PNA ok)     │ (inside AutoCAD) │
                                             └──────────────────┘
                                                        │
                                                AutoCAD .NET API
```

| Компонент | Язык | Расположение |
|-----------|----------|----------|
| **AutoCADMCPPlugin.dll** | C# | `src/AutoCADMCPPlugin/` |
| **MCP-сервер** | C# | `src/AutoCADMCP.Server/` |
| **Агент AutoCode** (необязательно) | C# | `src/AutoCADMCP.Agent/` |
| **Манифест бандла** | XML | `config/AutoCADMCPPlugin.bundle/` |

Всё написано на C#. MCP-сервер поставляется одним самодостаточным `.exe`, так что
на машине конечного пользователя не требуется устанавливать ничего, кроме самого AutoCAD.

### Где выполняется каждый инструмент

Из 184 инструментов 183 представляют собой команды внутри плагина и проксируются
напрямую. Два выполняются в процессе сервера, потому что им нужны библиотеки,
которым нечего делать в загруженном виде внутри `acad.exe`:

| Инструмент | Где выполняется | Почему |
|---|---|---|
| `create_table_from_excel` | сервер | читает `.xlsx`; плагин получает готовую геометрию через `bulk_create` |
| `plot_to_pdf` | оба | плагин печатает, затем сервер обрезает `MediaBox` точно по размеру листа |

Плагин намеренно не несёт зависимостей, кроме AutoCAD API и
Newtonsoft.Json — AutoCAD поставляет собственные копии распространённых сборок, а
конфликт версий внутри `acad.exe` — ошибка, из которой не восстановиться.

`tools.json` — зафиксированный в репозитории контракт на состав инструментов. `build/verify-assembly.ps1`
сверяет его с настоящим реестром команд и с собственным набором инструментов сервера,
так что каталог не может заявлять то, что никто не в состоянии обслужить.

### Как это работает

Плагин на C# загружается внутрь AutoCAD как надстройка и предоставляет один и тот же конвейер JSON-RPC сразу по **двум транспортам**:

1. **TCP-сокет на `localhost:8081`** — используется тем MCP-сервером, который вы запускаете; он передаёт 184 инструмента по stdio для Claude / Claude Code / Claude Desktop.
2. **HTTP на петлевом интерфейсе `localhost:8082`** — используется браузерными приложениями, которые не могут открывать сырые TCP-сокеты (вызов `fetch()` к `http://127.0.0.1:8082/jsonrpc` достаёт до любой команды в реестре, с заголовками CORS и поддержкой Chrome Private-Network-Access «из коробки»).

Оба транспорта проходят через один и тот же `JsonRpcHandler`, поэтому каждый инструмент (`create_line`, `create_table`, `capture_screenshot`, …) одинаково доступен с любого из путей. Команды передаются в главный UI-поток AutoCAD через `Application.Idle` + `DocumentLock` — за исключением инструментов интроспекции, которые отвечают напрямую, чтобы обнаружение инструментов продолжало работать, пока AutoCAD занят.

### Потокобезопасность

.NET API AutoCAD однопоточен. Плагин использует событие `Application.Idle` и `DocumentLock`, чтобы безопасно выполнять команды из потоков обработчика сокета в главном потоке.

### Выполнение кода (опционально, отдельный сервер)

Многошаговые построения, которые иначе обошлись бы в десятки обращений
туда-обратно, берёт на себя **агент AutoCode** (`src/AutoCADMCP.Agent/`), а не
инструмент этого сервера. Он просит Claude написать код на C# поверх описанного
выше набора инструментов и может затем его выполнить:

| Инструмент | Нужен AutoCAD | Нужно включённое выполнение |
|---|---|---|
| `agent_status` | нет | нет |
| `generate_drawing_code` | нет | нет |
| `draw` | да | да |

> **Выполнение по умолчанию выключено.** Задайте `AUTOCAD_AGENT_ALLOW_EXEC=1`,
> чтобы включить `draw`. Сгенерированный код не помещается в песочницу и
> выполняется с правами процесса агента; операции с чертежом всё равно проходят
> через проверки режима «только чтение» и подтверждения. `generate_drawing_code`
> не требует никаких разрешений и показывает вам код до того, как что-либо будет
> выполнено. См. [README агента](autocad-plugin/src/AutoCADMCP.Agent/README.md).

## Поддерживаемые версии AutoCAD

| Версия AutoCAD | Код выпуска | Целевая платформа .NET | Ссылка NuGet |
|----------------|--------------|-------------|-----------------|
| **2021, 2022, 2023, 2024** | R24.0–R24.3 | .NET Framework 4.8 (`net48`) | AutoCAD.NET 24.0.x |
| **2025, 2026** | R25.0–R25.1 | .NET 8 (`net8.0-windows`) | AutoCAD.NET 25.0.x |
| **2027** | R26.0 | .NET 10 (`net10.0-windows`) | AutoCAD.NET 26.0.x |

Ветка `net48` компилируется против **самых старых** эталонных сборок своего
семейства ABI (2021) — именно это позволяет одному двоичному файлу загружаться в
версиях с 2021 по 2024. Сборка против более новых эталонных сборок сломала бы
загрузку в старых выпусках.

`net48` и `net8.0-windows` собираются по умолчанию. Ветка 2027 добавляется
**автоматически, если на сборочной машине установлен AutoCAD 2027**, а там, где
его нет (например, в CI), её можно включить принудительно так:

```bash
dotnet build -c Release -p:IncludeNet10=true
```

Одна тонкость про 2027, о которой стоит знать: AutoCAD 2027 поставляет
собственный `Newtonsoft.Json` и загружает его в контекст по умолчанию. Если 2027
присутствует, сборка ссылается именно на *эту* сборку и никогда не копирует свою,
поэтому сигнатуры на этапе компиляции и на этапе выполнения совпадают — иначе во
время выполнения вы получите `MissingMethodException`. Указать сборке на
нестандартную установку можно через `-p:AutoCADPath2027="D:\...\AutoCAD 2027"`.

Манифест бандла (`PackageContents.xml`) объявляет по одному `ComponentEntry` на
каждый диапазон, поэтому AutoCAD сам выбирает нужную DLL. Все расхождения между
версиями изолированы в `Core/AcadCompat.cs` — ни одного `#if` больше нигде в
кодовой базе.

**AutoCAD LT не поддерживается** и поддерживаться не может: в LT нет `NETLOAD`, и
он не способен загружать .NET-плагины ни в одной версии. LT 2024 и новее
поддерживает только AutoLISP/ActiveX, для чего понадобился бы отдельный мост.

Вертикальные решения на базе AutoCAD (Civil 3D, Plant 3D, Map 3D, Mechanical,
Architecture) размещают тот же бандл и работают без изменений.

## Установка

### Что нужно заранее

- **AutoCAD 2021–2027** (любая редакция; LT не поддерживается — он не умеет загружать .NET-плагины)
- **Windows** (AutoCAD работает только под Windows)
- **.NET SDK** — только для сборки из исходников: SDK 8 закрывает ветки 2021–2026, для целевой платформы AutoCAD 2027 нужен **SDK 10**

### Вариант A: установщик из релиза (рекомендуется)

Скачайте `AutoCADMCP-Setup-<версия>.exe` из
[последнего релиза](../../releases/latest) и запустите **при закрытом
AutoCAD** — установщик сам проверяет `acad.exe` и откажется работать иначе:
файлы плагина были бы заблокированы, и установка легла бы наполовину.

Нужны права администратора: плагин кладётся в
`%ProgramData%\Autodesk\ApplicationPlugins\`, чтобы его подхватывали все
профили на машине. Оставьте набор компонентов по умолчанию — **Plugin and MCP
server**: вместе с плагином ставится самодостаточный сервер, а значит собирать
ничего не нужно и **шаг 3 ниже можно пропустить**. На последней странице
установщик называет найденные версии AutoCAD и путь к exe сервера.

Установщик не подписан, поэтому при первом запуске Windows SmartScreen выдаст
предупреждение: **«Подробнее»** → **«Выполнить в любом случае»**.

### Вариант B: переносимый бандл из релиза (без прав администратора)

Скачайте `AutoCADMCPPlugin-bundle-<версия>.zip` из того же релиза, распакуйте и
скопируйте папку `AutoCADMCPPlugin.bundle` в
`%APPDATA%\Autodesk\ApplicationPlugins\`. Так плагин ставится только для
текущего пользователя. MCP-сервера в этом архиве нет — соберите его по шагу 3.

### Вариант C: сборка из исходников

Если у вас установлен .NET SDK:

```bash
cd autocad-plugin
install.bat
```

Скрипт собирает все целевые платформы, доступные на машине, копирует DLL в `%APPDATA%\Autodesk\ApplicationPlugins\AutoCADMCPPlugin.bundle\`, проверяет, что папка каждого фреймворка действительно получила свою DLL, и AutoCAD загрузит плагин автоматически при запуске. В итоговой сводке сказано, была ли заполнена папка для AutoCAD 2027 или пропущена.

MCP-сервер представляет собой единственный самодостаточный exe, поэтому, когда плагин на месте, устанавливать больше нечего.

### Вариант D: ручная установка (копированием)

Если скрипты не работают, установить можно вручную:

1. Скопируйте папку `autocad-plugin/config/AutoCADMCPPlugin.bundle` в:
   ```
   %APPDATA%\Autodesk\ApplicationPlugins\
   ```
   > Подсказка: вставьте `%APPDATA%\Autodesk\ApplicationPlugins` в адресную строку Проводника Windows — путь развернётся автоматически.

2. Скопируйте DLL из `autocad-plugin/dist/net48/` в:
   ```
   %APPDATA%\Autodesk\ApplicationPlugins\AutoCADMCPPlugin.bundle\Contents\net48\
   ```

3. В итоге структура папок должна быть такой:
   ```
   %APPDATA%\Autodesk\ApplicationPlugins\
     └── AutoCADMCPPlugin.bundle\
           ├── PackageContents.xml
           └── Contents\
                 └── net48\
                       ├── AutoCADMCPPlugin.dll
                       └── Newtonsoft.Json.dll
   ```
   > Для AutoCAD 2025–2026 скопируйте также `dist/net8.0-windows/` в `Contents\net8.0-windows\`.
   >
   > Для AutoCAD 2027 папка должна называться `Contents\net10.0-windows\` и содержать `AutoCADMCPPlugin.dll`, `System.Drawing.Common.dll`, `Microsoft.Win32.SystemEvents.dll` и `System.Private.Windows.Core.dll` из `bin/Release/net10.0-windows/`. **Не** копируйте туда `Newtonsoft.Json.dll` — AutoCAD 2027 поставляется с собственной копией, а вторая копия в бандле может её перекрыть.

4. Откройте AutoCAD — плагин загрузится автоматически.

> `autocad-plugin/install-prebuilt.bat` раскладывает DLL, лежащие в
> `autocad-plugin/dist/`, ничего не собирая. Эти бинарники — снимок: там только
> `net48` и `net8.0-windows`, и они отстают от исходников и от релизов, поэтому
> установленный так плагин может не знать инструментов, описанных в этом README.
> Предпочтительны варианты A и B; скрипт нужен, только чтобы разложить именно
> этот снимок без доступа к сети.

### Шаг 2: запуск сервера в AutoCAD

```
Command: MCPSTART
[MCP] Server started on localhost:8081
```

Другие команды:
- `MCPSTOP` — остановить сервер
- `MCPSTATUS` — показать число подключений

### Шаг 3: получить MCP-сервер

**Если вы шли вариантом A, шаг можно пропустить** — установщик уже положил

В Claude Code или Claude Desktop:

> «Нарисуй окружность в точке (50, 50) радиусом 25»

Либо проверьте вручную через TCP-сокет:

```python
import socket, json
sock = socket.socket()
sock.connect(('localhost', 8081))
sock.sendall(json.dumps({
    "jsonrpc": "2.0", "method": "system_status", "params": {}, "id": "1"
}).encode() + b"\n")

```

Либо через HTTP-прослойку (именно её используют интеграции с браузером и веб-приложениями):

```bash
  -d '{"jsonrpc":"2.0","method":"system_status","params":{},"id":"1"}'
```

`MCPSTATUS` сообщит, что оба транспорта работают.

## Печать в PDF

`plot_to_pdf` печатает либо именованный лист, либо прямоугольное окно пространства модели через собственный механизм публикации AutoCAD, поэтому в PDF попадает ровно то, что показал бы предварительный просмотр печати, — со стилями печати, весами линий и всем прочим.

Формат бумаги — это то, что обычно застаёт людей врасплох. AutoCAD может печатать только на тот лист, который действительно определён устройством печати, и такие листы адресуются *каноническими* именами носителей вроде `ISO_full_bleed_A1_(841.00_x_594.00_MM)`, а не локализованными строками, которые показывает диалог печати. Инструмент `plot_devices` перечисляет то, что предлагает устройство: вызовите его без аргументов, чтобы получить устройства печати и таблицы стилей печати, установленные на машине, плюс форматы бумаги драйвера PDF по умолчанию, либо передайте `device` (синоним `plotter` тоже принимается, потому что некоторые MCP-хосты перехватывают аргумент с буквальным именем `device` ещё до того, как его увидит инструмент) вместе с необязательной подстрокой `filter`, чтобы сузить длинный список. Каждая запись возвращается вместе с областью печати и полями, так что вызывающая сторона может отличить лист с печатью в край от листа с полем 5 мм ещё до выбора.

Если оставить `paper` в значении по умолчанию `auto`, всё это можно пропустить: команда измеряет печатаемое окно и выбирает наименьший из определённых листов, который его вмещает, отдавая предпочтение той ориентации, для которой не требуется поворот, если лист существует в обеих. Поскольку наименьший лист, *вмещающий* окно, редко совпадает по размеру с самим окном, готовая страница затем обрезается по напечатанным границам, а излишек удаляется, и в ответе сообщаются `trimmed`, `trimmed_size_mm` и применённый `trim_box_mm`. Передайте `trim: false`, чтобы оставить страницу драйвера ровно такой, какой она получилась.

Обрезка выполняется в MCP-сервере с помощью [PdfSharp](https://www.nuget.org/packages/PdfSharp), которая скомпилирована внутрь, — сам плагин не несёт библиотеки для работы с PDF, потому что загрузка такой библиотеки внутри `acad.exe` рискует перекрыть сборку, которая уже поставляется с AutoCAD. Неудачная обрезка никогда не срывает печать: в ответе просто указывается `trimmed: false` с полем `trim_error`, объясняющим причину. Обрезка отмеряется от реального `MediaBox` файла, созданного AutoCAD, а не от номинальных размеров листа, потому что `DWG To PDF.pc3` квантует страницу с шагом около 0,042 мм на единицу, и номинальный лист 841 × 594 мм получается размером 841,022 × 594,078 мм.

Для обеих команд действует одно предварительное условие: чертёж должен быть открыт. Устройства печати, таблицы стилей и форматы бумаги считываются через `PlotSettingsValidator.Current`, который является текущим *для активного документа*, поэтому без открытого чертежа их просто неоткуда прочитать. Обе команды проверяют наличие активного документа, прежде чем обращаться к API печати, и возвращают понятную ошибку с объяснением, что делать.

## Вызов из браузера или веб-приложения

HTTP-прослойка делает полный набор из 80 команд плагина доступным из любого внутреннего инструмента на базе браузера — без MCP-клиента, без участия Claude, без лицензии на каждого инженера. Инженеры один раз запускают плагин (`MCPSTART` в AutoCAD), а ваше веб-приложение обращается напрямую к `localhost:8082`.

### Быстрый пример: вставка таблицы

```js
async function insertBeamSchedule(beams) {
  const r = await fetch('http://127.0.0.1:8082/jsonrpc', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      jsonrpc: '2.0',
      id: '1',
      method: 'create_table',
      params: {
        position: [0, 0, 0],
        title: 'Beam schedule',
        rows: beams.length,
        columns: 8,
        row_height: 500,
        column_width: 2000,
        layer: 'BEAM_SCHEDULE',
        data: [
          ['Beam ID', 'b×D', 'L (m)', 'Top', 'Bot', 'Stirrups', 'Side-face', 'Status'],
          ...beams.map(b => [b.id, b.section, b.length, b.top, b.bot, b.stirrups, b.sideFace, b.status]),
        ],
      },
    }),
  });
  return r.json();
}
```

### Цветные заливки (полосы заголовков, цветовые метки статуса)

`create_hatch` и ветка `hatch` в `bulk_create` принимают `color` (ACI 0–255) и `true_color` `[r, g, b]` (приоритет над ACI). Для залитых ячеек используйте образец `SOLID`, ту же границу, которую ячейка уже использует для линий сетки, и цвет окажется *позади* любого текста, нарисованного поверх:

```js
{
  jsonrpc: '2.0', id: '2', method: 'bulk_create',
  params: {
    entities: [
      // тёмно-зелёная полоса строки заголовка, RGB зафиксирован по фирменному цвету
      {
        type: 'hatch',
        params: {
          boundary: [[0, 0], [12000, 0], [12000, 600], [0, 600]],
          pattern: 'SOLID',
          true_color: [37, 78, 55],
          layer: 'TABLE_HEADER'
        }
      },
      // линии сетки, текст и прочее — рисуются после, поэтому лежат сверху
    ]
  }
}
```

Ограничивающей полилинии штриховки назначается тот же цвет, чтобы она не проступала контуром `ByLayer` на фоне заливки.

### Подгонка таблиц под реальную ширину текста

Глифы шрифтов SHX (Romans, Standard, Romantic, RomanD, Italic, Italicc) пропорциональны и подогнаны вручную; приближённый расчёт в пикселях на JS заметно расходится с реальной отрисовкой. Вызывающая сторона в браузере, строящая таблицы, может спросить у AutoCAD, каковы фактические размеры текста, прежде чем задавать ширину столбцов:

```js
const r = await fetch('http://127.0.0.1:8082/jsonrpc', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    jsonrpc: '2.0', id: '1', method: 'measure_texts',
    params: {
      items: [
        { text: 'BEAM',                 height: 225, style: 'Romans' },
        { text: 'SIZE',                 height: 225, style: 'Romans' },
        { text: 'BOTTOM REINFORCEMENT', height: 225, style: 'Romans' },
        { text: 'GB-400x700',           height: 225, style: 'Romans' },
      ],
    },
  }),
});
// → { results: [{ text, width, height }, ...] }   ширины по реальным границам DBText
```

`measure_text` — вариант для одной строки. Оба работают так: в пространство модели добавляется временный пробный объект `DBText`, читаются его `GeometricExtents`, а транзакция прерывается, поэтому проба никогда не попадает в чертёж пользователя. Пакеты ограничены 2000 элементами на вызов, чтобы вышедший из-под контроля клиент не занял основной поток AutoCAD.

### CORS

По умолчанию слушатель разрешает любой источник (`*`), чтобы внутренние инструменты работали без настройки. **Для промышленных развёртываний зафиксируйте свой реальный источник**, задав переменную окружения до запуска AutoCAD:

```bat
setx AUTOCAD_MCP_HTTP_ORIGINS "https://your-internal-app.example.com"
```

Несколько источников перечисляются через запятую. Заголовок `Access-Control-Allow-Private-Network: true` отправляется всегда, чтобы предварительный запрос Chrome по Private Network Access проходил, когда HTTPS-страница обращается к `127.0.0.1`.

### Отключение HTTP-прослойки

Задайте `AUTOCAD_MCP_HTTP_PORT=0` в окружении пользователя, чтобы полностью отключить HTTP-слушатель (TCP на порту 8081 продолжит работать для Claude).

## Добавление новых команд

1. Создайте класс, наследующий `AcadCommand`, в каталоге `Commands/`
2. **Зарегистрируйте его** в `Core/CommandRegistry.cs` — регистрация выполняется явно, а не
   через рефлексию, поэтому новый класс ничего не делает, пока не зарегистрирован
3. Добавьте соответствующий инструмент MCP в `server.py`
4. Пересоберите и переустановите: `install.bat`

Пример:

```csharp
public class MyCommand : AcadCommand
{
    public override string MethodName => "my_command";

    public override CommandResult Execute(JObject parameters)
    {
        Document doc = Application.DocumentManager.MdiActiveDocument;
        if (doc == null) return CommandResult.NoDoc();

        // Снисходительные псевдонимы: принимаются id | entity_id | handle | object_id
        string handle = EntityHelper.EntityIdArg(parameters);
        if (string.IsNullOrWhiteSpace(handle))
            return CommandResult.BadParam("Parameter 'id' is required");

        using (EntityHelper.LockDoc())
        using (Transaction tr = doc.Database.TransactionManager.StartTransaction())
        {
            ObjectId id = EntityHelper.ResolveHandle(doc.Database, handle);
            if (id.IsNull) return CommandResult.NotFound($"Entity '{handle}' not found");

            // Здесь ваш код работы с API AutoCAD
            tr.Commit();
        }
        return CommandResult.Ok(new JObject { ["message"] = "Done" });
    }
}
```

Затем в `Core/CommandRegistry.cs`:

```csharp
Register(new MyCommand());
```

**Классификация «чтение / запись / разрушающая операция» выполняется автоматически.** `CommandClassifier` выводит
её из имени метода (`list_`/`get_`/`measure_` → чтение; `erase_`/`delete_`/
`purge_` → разрушающая). Переопределяйте `IsWrite` или `IsDestructive` в своём классе, когда
имя вводит в заблуждение — например, `measure_entity` по префиксу выглядит как «только чтение», но
на самом деле расставляет маркеры, поэтому переопределяет `IsWrite => true`.

**Команды, которые вообще не обращаются к API AutoCAD** (интроспекция, настройки), следует
наследовать от `DirectCommand`. Они выполняются в потоке сокета и остаются отзывчивыми
даже тогда, когда AutoCAD занят или показывает модальный диалог.

## Модель безопасности

Перед выполнением любой команды срабатывают две проверки безопасности:

| Проверка | Поведение | По умолчанию |
|------|-----------|---------|
| **Режим «только чтение»** | Отклоняет любой инструмент, изменяющий чертёж, с `errorCode: ReadOnly` | выключен |
| **Подтверждение разрушающих операций** | `erase_*`/`delete_*`/`purge_*`/`overkill`/`ungroup`/`detach_*` требуют `"__confirm": true` | **включено** |

Обе переключаются через `set_server_options`. Разрушающих инструментов десять; вызовите
`get_capabilities`, чтобы получить текущий список. Каждый из них принимает `confirm` в собственной
схеме, так что клиент MCP действительно может отправить подтверждение — разрушающий инструмент,
в схеме которого его нет, невозможно выполнить, его можно только отклонить.

Каждый вызов дописывается в журнал вызовов по пути
`%APPDATA%\AutoCADMCP\activity.jsonl` (по одному объекту JSON на строку, с полями
пользователь/машина/чертёж/длительность/errorCode). Отключается через
`set_server_options({"audit_log": false})`.

## Коды ошибок

Сбои несут типизированный код в `error.data.errorCode`, чтобы клиент мог ветвиться по
виду сбоя, а не сопоставлять текст ошибки:

`NotFound` · `InvalidParam` · `ReadOnly` · `NoDocument` · `NeedsConfirm` ·
`Unsupported` · `TxnFailed` · `Timeout` · `Internal`

## Когда мост замолкает

У молчания четыре причины, и они требуют четырёх разных ответов, поэтому ни
сервер, ни плагин не сообщают о нём как об одной ошибке.

Вызов, который так и не дошёл до AutoCAD, классифицируется сервером до того, как о нём
будет сообщено: ошибка сокета сопоставляется с просмотром списка процессов, потому что
«AutoCAD не запущен», «AutoCAD запущен, но плагин так и не был стартован»
и «порт заблокирован» отклоняют подключение к петлевому интерфейсу совершенно одинаково.

| Что вы видите | Что это значит | Что делать |
|---|---|---|
| `AUTOCAD IS NOT RUNNING: there is no acad.exe process` | Слушать некому | Запустите AutoCAD, откройте чертёж, выполните `MCPSTART` |
| `AutoCAD IS running … THE PLUGIN IS NOT UP` | Пакет так и не был загружен, `MCPSTART` не выполнялся в этом сеансе или плагин умер, а AutoCAD выжил | Выполните `MCPSTART` |
| `Connecting to … was DENIED` | Не отказ, а запрет: брандмауэр, антивирус или другой процесс, удерживающий порт | Найдите владельца через `netstat -ano` и поищите порт 8081 |
| `… was open and died in the middle of a call … AUTOCAD ITSELF TERMINATED` | AutoCAD упал или был закрыт во время вызова | Перезапустите AutoCAD и посмотрите, предложит ли он восстановить несохранённую работу |

Там, где соединение раньше работало, сообщение дополнительно указывает, когда плагин отвечал
в последний раз, что отделяет «никогда не работало» от «перестало работать». `--check` использует
те же формулировки.

Вызов, который дошёл до плагина и затем завершился по таймауту, — другое дело, и таймаут
говорит, какое именно: каждый вызов передаётся в главный поток AutoCAD через
`Application.Idle`, поэтому давность последнего такта простоя и есть признак. `Idle` продолжает
срабатывать, пока команда стоит на приглашении командной строки — мост отвечает, но всё, что
отправлено следующим, будет съедено как ответ на это приглашение, поэтому сначала вызывайте
`cancel_command`. `Idle` не срабатывает вовсе, пока открыт модальный диалог: главный поток
никогда не возвращается, ничто из того, что может сделать плагин, диалог не закроет, и кому-то
придётся закрыть его вручную. `system_status` сообщает оба состояния по `CMDACTIVE` / `CMDNAMES`
раньше, чем вы начнёте гадать.

## Работа с несколькими чертежами

Каждый инструмент работает с *активным* документом, и `drawing_open` — единственное, что
меняет, какой документ активен. Поэтому цикл по файлам должен находиться вне
AutoCAD: открыть, изменить, сохранить или закрыть, перейти к следующему.

Соблазнительно управлять тем же циклом из LISP внутри AutoCAD, но это отказывает тремя
способами, которые вообще не дают ошибки. Чертёж, открытый через ObjectDBX
(`vla-Open`), никогда не становится активным, поэтому `ssget "_X"` продолжает выбирать из
исходного — скрипт сообщает об успехе по каждому файлу и не меняет ничего. `entmod`
не работает с объектами ObjectDBX, у которых своя объектная модель. `entdel`
удаляет объекты только из пространства модели и пространства листа; получив объект внутри
определения блока, он молча оставляет его на месте, и вместо этого блок приходится
переопределять.

Четвёртый случай не молчаливый, а фатальный: смена активного документа из LISP,
который сам выполняется в контексте документа (`vla-put-ActiveDocument`,
`Documents.Open` с активацией), разрушает контекст выполняющегося кода и
роняет процесс AutoCAD без единого сообщения.

Поскольку отказы молчаливы, проверяйте пакетный прогон измерением или подсчётом —
`list_entities`, `select_by_properties`, `measure_area`, — а не считайте
отсутствие ошибок доказательством того, что работа выполнена.
